# 2.6 `Stack<T>`

`Stack<T>` represents a **LIFO** collection:

> **Last In, First Out**

The item added last is the item removed first.

```text
        Top
         |
         v
    +---------+
    | Charlie |  <- first out
    +---------+
    |   Bob   |
    +---------+
    |  Alice  |
    +---------+
```

If we add:

```csharp
var stack = new Stack<string>();

stack.Push("Alice");
stack.Push("Bob");
stack.Push("Charlie");
```

Then `Charlie` is at the top.

---

## 1. Creating a Stack

```csharp
Stack<int> numbers = new Stack<int>();
```

Or:

```csharp
var numbers = new Stack<int>();
```

You can also initialize it with values:

```csharp
var numbers = new Stack<int>
{
    10,
    20,
    30
};
```

---

## 2. `Push()`

`Push()` adds an item to the **top** of the stack.

```csharp
stack.Push("Alice");
stack.Push("Bob");
stack.Push("Charlie");
```

The result is conceptually:

```text
Top
 |
 v
+---------+
| Charlie |
+---------+
|   Bob   |
+---------+
|  Alice  |
+---------+
```

`Push()` is normally **O(1) amortized**.

---

## 3. `Pop()`

`Pop()` removes and returns the item at the top.

```csharp
string person = stack.Pop();

Console.WriteLine(person);
```

Output:

```text
Charlie
```

The stack becomes:

```text
Top
 |
 v
+-----+
| Bob |
+-----+
|Alice|
+-----+
```

`Pop()` is normally **O(1)**.

### Important

Calling `Pop()` on an empty stack throws:

```text
InvalidOperationException
```

If an empty stack is a normal possibility, use `TryPop()`.

---

## 4. `TryPop()`

`TryPop()` safely attempts to remove the top element.

```csharp
if (stack.TryPop(out string? person))
{
    Console.WriteLine(person);
}
```

If the stack contains an item:

```text
true
person = item
```

If the stack is empty:

```text
false
```

No exception is thrown.

`TryPop()` is **O(1)**.

---

## 5. `Peek()`

`Peek()` returns the top item **without removing it**.

```csharp
string person = stack.Peek();
```

For:

```text
+---------+
| Charlie | <- top
+---------+
|   Bob   |
+---------+
|  Alice  |
+---------+
```

`Peek()` returns `Charlie`, but the stack remains unchanged.

`Peek()` is **O(1)**.

Like `Pop()`, `Peek()` throws `InvalidOperationException` if the stack is empty.

---

## 6. `TryPeek()`

The safe version is:

```csharp
if (stack.TryPeek(out string? person))
{
    Console.WriteLine(person);
}
```

It returns `false` if the stack is empty.

`TryPeek()` is **O(1)**.

---

## 7. `Count`

`Count` tells you how many elements are currently in the stack.

```csharp
Console.WriteLine(stack.Count);
```

`Count` is **O(1)**.

Remember the distinction:

```text
Count    = number of elements currently stored
Capacity = amount of internal storage
```

---

## 8. Capacity

Like `Queue<T>`, `Stack<T>` has an internal capacity.

You can specify an initial capacity:

```csharp
var stack = new Stack<int>(100);
```

This allocates enough initial storage for approximately 100 elements.

Capacity is **not a maximum size**.

If you add more:

```csharp
for (int i = 0; i < 200; i++)
{
    stack.Push(i);
}
```

the stack automatically grows.

You can also ensure a minimum capacity:

```csharp
stack.EnsureCapacity(500);
```

This doesn't add any elements. It only ensures that enough internal storage is available.

### Why specify capacity?

If you know you're going to add a large number of items, providing an appropriate initial capacity can reduce the number of internal resizing operations and associated copying.

---

## 9. `Contains()`

You can check whether an item exists:

```csharp
bool exists = stack.Contains("Alice");
```

This requires searching through the stack.

Complexity:

```text
O(n)
```

A `Stack<T>` is designed for LIFO operations, not fast arbitrary lookup.

---

## 10. `Clear()`

Removes all elements:

```csharp
stack.Clear();
```

Afterwards:

```csharp
stack.Count == 0
```

`Clear()` is generally **O(n)** because the references to the stored elements need to be cleared.

---

## 11. Interfaces implemented by `Stack<T>`

`Stack<T>` implements:

```text
IEnumerable<T>
IEnumerable
IReadOnlyCollection<T>
ICollection
ICollection<T>
```

Conceptually:

```text
Stack<T>
   |
   +-- ICollection<T>
   |      |
   |      +-- IEnumerable<T>
   |             |
   |             +-- IEnumerable
   |
   +-- IReadOnlyCollection<T>
```

This means you can pass a `Stack<T>` to something expecting an `IEnumerable<T>`:

```csharp
IEnumerable<int> numbers = stack;
```

But you won't have access to stack-specific operations through that interface:

```csharp
numbers.Pop(); // Doesn't exist
```

The interface controls what operations are exposed.

---

## 12. How `Stack<T>` is implemented

`Stack<T>` uses an **array-based implementation**.

Conceptually:

```text
Internal array:

+-----+-----+-----+-----+-----+
|  A  |  B  |  C  |     |     |
+-----+-----+-----+-----+-----+
              ^
              |
             Top
```

Unlike a `Queue<T>`, it doesn't need a circular buffer because insertion and removal happen at the same end.

When the internal array becomes full, the stack grows its underlying storage.

That resizing operation requires copying elements and is **O(n)**.

Therefore:

- `Push()` = **O(1) amortized**
- `Pop()` = **O(1)**
- `Peek()` = **O(1)**

---

## 13. Complexity

| Operation | Complexity |
|---|---:|
| `Push()` | O(1) amortized |
| `Pop()` | O(1) |
| `TryPop()` | O(1) |
| `Peek()` | O(1) |
| `TryPeek()` | O(1) |
| `Count` | O(1) |
| `Contains()` | O(n) |
| `Clear()` | O(n) |

The important distinction is again **amortized O(1)** for `Push()` because occasional resizing can require O(n) work.

## 14. Practical example: undo functionality

A stack is a natural fit for undo operations.

Suppose a user performs:

```text
Type "Hello"
Type " World"
Delete "World"
```

You could store previous states in a stack:

```text
Top
 |
 v
+----------------+
| "Hello World"  |
+----------------+
| "Hello"        |
+----------------+
| ""             |
+----------------+
```

When the user presses Undo:

```csharp
var previousState = history.Pop();
```

The most recent state is restored first.

That's exactly LIFO behavior.

---

## 15. `Stack<T>` vs `Queue<T>`

This is a common interview question.

| `Stack<T>` | `Queue<T>` |
|---|---|
| LIFO | FIFO |
| Last in, first out | First in, first out |
| `Push()` | `Enqueue()` |
| `Pop()` | `Dequeue()` |
| `Peek()` | `Peek()` |
| Top | Front |

Illustration:

```text
Stack:

    C  <- first out
    B
    A


Queue:

A -> B -> C
^
first out
```

Use a stack when the **most recently added item should be processed first**.

Use a queue when the **oldest item should be processed first**.

---

## 16. Stack and recursion

Stacks are also closely related to how method calls work.

For example:

```csharp
void A()
{
    B();
}

void B()
{
    C();
}

void C()
{
}
```

Conceptually:

```text
        C()
        ---
        B()
        ---
        A()
        ---
       Main()
```

When `C()` finishes, it is removed from the call stack. Then `B()` continues.

This is one reason stacks are commonly used for problems involving:

- recursion
- depth-first search
- expression evaluation
- undo/redo
- backtracking

## Interview questions

### Why is `Stack<T>.Pop()` O(1)?

Because the stack keeps track of its top position. Removing the top element doesn't require shifting the remaining elements.

### Why is `Push()` amortized O(1)?

Most pushes simply place the element into the next available position. Occasionally the underlying array needs to grow, requiring O(n) copying.

### When would you use `Stack<T>` instead of `Queue<T>`?

Use `Stack<T>` when you need LIFO behavior, where the most recently added item should be processed first.

### What happens when you call `Pop()` on an empty stack?

It throws `InvalidOperationException`.

If an empty stack is expected, use:

```csharp
TryPop()
```

instead.

### What is the difference between `Peek()` and `Pop()`?

`Peek()` returns the top element **without removing it**.

`Pop()` returns the top element **and removes it**.

---

## What you should remember

For an interview, the core answer is:

> `Stack<T>` is a generic LIFO collection. You add elements with `Push()`, remove them with `Pop()`, and inspect the top element with `Peek()`. It is array-based, so push is amortized O(1), while pop and peek are O(1). It also has `Count` and `Capacity`, and implements interfaces such as `ICollection<T>`, `IReadOnlyCollection<T>`, and `IEnumerable<T>`.
