# Part 2 — Collections

Collections are data structures that let you store, organize, access, and modify groups of values.

For a .NET backend developer, collections are especially important when processing API responses, handling data from a database, managing caches, building lookup tables, and writing performant code.

We'll cover your listed topics in sequence, including the internal mechanics, Big-O characteristics, practical tradeoffs, and interview scenarios.

# 2.1 Arrays

An array is a fixed-size, indexed collection of elements of the same type.

C#

```
int[] numbers = { 10, 20, 30, 40 };

Console.WriteLine(numbers[0]); // 10
Console.WriteLine(numbers[2]); // 30

numbers[1] = 25;
```

Once created, the array's length cannot change. You can modify its elements, but you cannot add or remove elements from the array itself.

## How arrays work internally

An array stores its elements in a contiguous region of memory. This means the elements are laid out next to each other in the array's storage.

The runtime knows:

* The starting location of the array's elements.

* The size of each element.

* The array's length.

To access an element, it calculates its location using the index.

Conceptually:

`Element address = Base address + (Index × Element size)`

This is why accessing an array element by index takes constant time, O(1)O(1)O(1).

Conceptual array layout
```
+------------------------+
| 10 | 20 | 30 | 40 | 50 |
+------------------------+
| 0  | 1  | 2  | 3  | 4  |
+------------------------+
```
Each index identifies an element directly.

For an array of value types such as `int[]`, the values themselves are stored in the array's element storage. For an array of reference types such as `Person[]`, the array stores references to objects, not the objects themselves.

The array object itself is a reference type and is typically allocated on the managed heap, although runtime optimizations and special cases can affect physical allocation details.

## Common array operations

| Operation                      | Typical time complexity |
| ------------------------------ | ----------------------- |
| Access by index                | O(1)                    |
| Update by index                | O(1)                    |
| Search for a value             | O(n)                    |
| Iterate through all elements   | O(n)                    |
| Copy the entire array          | O(n)                    |
| Insert or remove in the middle | O(n)                    |

Arrays are useful when:

* The number of elements is known and fixed.

* You need fast indexed access.

* You want low overhead and predictable storage.

* You need to work with APIs that require arrays, such as some low-level or interop APIs.

A common interview question is: Why is array indexing O(1), but searching for a value O(n)?

Because indexing calculates the element's location directly, while an unsorted array may require checking each element until the target is found.


## Interview questions and scenarios

Q1. Can you change the size of an array after creating it?

No. The array's length is fixed. If you need a different size, you must create another array and copy the elements, or use a resizable collection such as `List<T>`.

Q2. What happens when you access an invalid index?

The runtime throws an `IndexOutOfRangeException`.

C#

```
int[] values = { 1, 2, 3 };

Console.WriteLine(values[3]); // Exception
```

Valid indices range from `0` to `Length - 1`.

Q3. What's the difference between a multidimensional array and a jagged array?

C#

```
// Rectangular, two-dimensional array
int[,] matrix = new int[2, 3];

// Jagged array: an array of arrays
int[][] jagged = new int[2][];
jagged[0] = new int[3];
jagged[1] = new int[5];
```

A rectangular array has a fixed number of dimensions and a regular shape. A jagged array can have inner arrays of different lengths.

Q4. Scenario: You receive 10,000 records from an API and need to access them by index, but won't add or remove elements. Would you use an array?

An array is a reasonable choice, particularly if the size is fixed and you don't need collection-specific functionality. However, a `List<T>` may be more convenient if the data is being built incrementally or if other APIs expect a list. Both offer O(1) indexed access.

Q5. Scenario: You need to insert an item at the beginning of a large array repeatedly. What is the performance concern?

Every insertion requires shifting existing elements or creating a new array and copying them. Each insertion is O(n), so repeated front insertions can become expensive. A different data structure may be more appropriate depending on how the data is accessed.

What to remember: Arrays provide fixed-size storage and fast indexed access. They are a foundational structure that helps explain how `List<T>` works internally.

> Arrays in C# — Initialization, Operations, and Sorting

Let's go deeper into arrays, covering one-dimensional, multidimensional, and jagged arrays, along with common operations and important methods from the `Array` API.

### 1. Different ways to initialize arrays

#### 1.1 One-dimensional arrays

A one-dimensional array stores elements in a single sequence.

C#

```
// Declare and initialize with a fixed size
int[] numbers = new int[5];

// Initialize with values
int[] a = new int[] { 10, 20, 30 };

// Shorthand initialization
int[] b = { 10, 20, 30 };

// Target-typed array creation
int[] c = new[] { 10, 20, 30 };

// Using collection expressions (C# 12+)
int[] d = [10, 20, 30];

// Declare first, initialize later
int[] e;
e = new int[] { 10, 20, 30 };
```

If you allocate an array with a size but don't provide values, its elements receive default values.

C#

```
int[] numbers = new int[3];
// [0, 0, 0]

string?[] names = new string?[3];
// [null, null, null]
```

The default value depends on the element type. For example, numeric value types default to zero, `bool` defaults to `false`, and reference types default to `null`.

#### 1.2 Two-dimensional rectangular arrays

A rectangular array has a fixed number of dimensions. A two-dimensional array is often visualized as rows and columns.

C#

```
// Allocate 2 rows and 3 columns
int[,] matrix = new int[2, 3];

// Initialize with values
int[,] a = new int[,]
{
    { 1, 2, 3 },
    { 4, 5, 6 }
};

// Shorthand initialization
int[,] b =
{
    { 1, 2, 3 },
    { 4, 5, 6 }
};

// Collection expression is not the syntax for rectangular arrays.
```

Access an element using two indices:

C#

```
Console.WriteLine(matrix[0, 1]);
matrix[1, 2] = 99;
```

You can get the size of each dimension:

C#

```
Console.WriteLine(matrix.GetLength(0)); // Number of rows: 2
Console.WriteLine(matrix.GetLength(1)); // Number of columns: 3
```

#### 1.3 Three-dimensional rectangular arrays

A three-dimensional array adds another dimension, often visualized as multiple two-dimensional layers.

C#

```
int[,,] cube = new int[2, 3, 4];

int[,,] values =
{
    {
        { 1, 2 }, 
        { 3, 4 }
    },
    {
        { 5, 6 },
        { 7, 8 }
    }
};
```

The second example has a shape of `2 × 2 × 2`.

Access values with three indices:

C#

```
cube[0, 1, 2] = 42;

Console.WriteLine(cube[0, 1, 2]);
```

You can extend the same concept to arrays with more dimensions, such as `int[,,,]`. In practice, arrays with many dimensions are less common.

##### Can I use `{ [] }` to initialize an array?

It depends on the type of array and the C# syntax you're using.

For a traditional rectangular array, use nested braces:

C#

```
int[,] matrix =
{
    { 1, 2 },
    { 3, 4 }
};
```

The rectangular array has two dimensions, so its initializer describes rows and columns.

For a jagged array, you can use nested braces:

C#

```
int[][] jagged =
{
    new[] { 1, 2 },
    new[] { 3, 4, 5 }
};
```

With C# 12 collection expressions, you can also write:

C#

```
int[][] jagged =
[
    [1, 2],
    [3, 4, 5]
];
```

And this form can work too:

C#

```
int[][] jagged =
{
    [],
    []
};
```

Here, the inner `[]` expressions are target-typed collection expressions. The compiler knows they need to produce `int[]` values because the outer array is `int[][]`.

The key distinction:

* `{ ... }` is the traditional array initializer syntax.

* `[ ... ]` is the newer collection expression syntax introduced in C# 12.

* For a rectangular multidimensional array such as `int[,]`, use the traditional nested-brace initializer. The C# 12 collection expression syntax doesn't directly initialize a multidimensional array.

#### 1.4 Jagged arrays

A jagged array is an array whose elements are themselves arrays. Each inner array can have a different length.

C#

```
// Declare and allocate the outer array
int[][] jagged = new int[3][];

// Allocate each inner array separately
jagged[0] = new int[2];
jagged[1] = new int[4];
jagged[2] = new int[3];
```

You can initialize everything at once:

C#

```
int[][] values =
{
    new int[] { 1, 2 },
    new int[] { 3, 4, 5, 6 },
    new int[] { 7, 8, 9 }
};
```

With collection expressions (C# 12+):

C#

```
int[][] values =
[
    [1, 2],
    [3, 4, 5, 6],
    [7, 8, 9]
];
```

Access an element with two indices:

C#

```
Console.WriteLine(values[1][2]); // 5
```

Unlike a rectangular array, the jagged array doesn't require every row to have the same length.

##### Can jagged arrays have more than two dimensions?

Yes. A jagged array is an array whose elements are themselves arrays. You can nest arrays to any number of levels.

For example, a 3-level jagged array:

C#

```
int[][][] data = new int[2][][];

data[0] = new int[2][];
data[0][0] = new int[] { 1, 2 };
data[0][1] = new int[] { 3, 4, 5 };

data[1] = new int[1][];
data[1][0] = new int[] { 6, 7, 8, 9 };
```

You can access an element like this:

C#

```
data[1][0][2]; // 8
```

Unlike a rectangular 3D array, the nested arrays don't have to have the same lengths. This makes jagged arrays useful when each group has a different number of elements.

Compare:

C#

```
int[,,] rectangular = new int[2, 3, 4];
int[][][] jagged = new int[2][][];
```

The rectangular array has fixed lengths for each dimension. The jagged array has independently allocated inner arrays, so its shape can vary.

#### Rectangular vs. jagged

```
Rectangular array (int[,])      Jagged array (int[][])

+---+---+---+                   +----------+
| 1 | 2 | 3 |                   | [1, 2]   |
+---+---+---+                   +----------+
| 4 | 5 | 6 |                   | [3, 4, 5]|
+---+---+---+                   +----------+
                                | [6]      |
                                +----------+
```

* Rectangular arrays have a uniform shape and use comma-separated indices, such as `matrix[1, 2]`.

* Jagged arrays consist of separate inner arrays and use chained indexing, such as `jagged[1][2]`.

* Jagged arrays can have rows of different lengths.

* Rectangular arrays can be useful for matrices and grids. Jagged arrays are useful when rows have different sizes or can be managed independently.

### 2. Iterating through arrays

There are several ways to iterate through arrays. The right approach depends on whether you need the index, want to modify elements, or are working with multiple dimensions.

#### 2.1 `for` loop

Use `for` when you need the index or want to update elements.

C#

```
int[] numbers = { 10, 20, 30 };

for (int i = 0; i < numbers.Length; i++)
{
    Console.WriteLine(numbers[i]);
}

// Modify elements
for (int i = 0; i < numbers.Length; i++)
{
    numbers[i] *= 2;
}
```

#### 2.2 `foreach` loop

Use `foreach` when you only need to read or process each element.

C#

```
int[] numbers = { 10, 20, 30 };

foreach (int number in numbers)
{
    Console.WriteLine(number);
}
```

You cannot assign to the iteration variable to modify the array element:

C#

```
foreach (int number in numbers)
{
    // number *= 2; // Does not modify the array element
}
```

#### 2.3 `foreach` with indices

In modern C#, you can use `foreach` with `Enumerable.Range`, but that involves LINQ. For straightforward indexed iteration, `for` is usually simpler.

#### 2.4 Iterating over multidimensional arrays

A `foreach` loop visits every element in a multidimensional array.

C#

```
int[,] matrix =
{
    { 1, 2, 3 },
    { 4, 5, 6 }
};

foreach (int value in matrix)
{
    Console.WriteLine(value);
}
```

To access row and column indices, use nested loops:

C#

```
for (int row = 0; row < matrix.GetLength(0); row++)
{
    for (int col = 0; col < matrix.GetLength(1); col++)
    {
        Console.WriteLine(matrix[row, col]);
    }
}
```

##### Why does `GetLength(0)` return rows and `GetLength(1)` return columns?

A rectangular array in C# has dimensions (also called ranks) numbered from zero.

For example:

C#

```
int[,] matrix =
{
    { 1, 2, 3 },
    { 4, 5, 6 }
};
```

Think of the dimensions this way:

* Dimension `0` describes the vertical direction: how many rows there are.

* Dimension `1` describes the horizontal direction: how many columns there are.

So:

C#

```
matrix.GetLength(0); // 2 rows
matrix.GetLength(1); // 3 columns
```

This is a convention for how C# rectangular arrays are indexed. It isn't a universal rule for every language or every kind of matrix.

##### What about a 3D array?

Consider:

C#

```
int[,,] cube = new int[2, 3, 4];
```

It has three dimensions:

C#

```
cube.GetLength(0); // 2
cube.GetLength(1); // 3
cube.GetLength(2); // 4
```

You can imagine it as:

* Dimension 0: 2 layers

* Dimension 1: 3 rows per layer

* Dimension 2: 4 columns per row

The actual indexing uses all three coordinates:

C#

```
cube[0, 1, 2] = 42;
```

The terms layer, row, and column are a useful way to visualize a 3D array, but the fundamental concept is simply three dimensions.

#### 2.5 Iterating over jagged arrays

Each inner array may have a different length, so use the length of each row.

C#

```
int[][] jagged =
{
    new[] { 1, 2 },
    new[] { 3, 4, 5 },
    new[] { 6 }
};

for (int row = 0; row < jagged.Length; row++)
{
    for (int col = 0; col < jagged[row].Length; col++)
    {
        Console.WriteLine(jagged[row][col]);
    }
}
```

### 3. Copying arrays

Arrays are reference types. Assigning one array variable to another copies the reference, not the elements.

C#

```
int[] original = { 1, 2, 3 };
int[] reference = original;

reference[0] = 99;

Console.WriteLine(original[0]); // 99
```

Both variables refer to the same array.

If you need a separate array, use one of the following methods.

#### 3.1 `Array.Copy()`

`Array.Copy()` copies elements from one array to another.

C#

```
int[] original = { 1, 2, 3 };
int[] copy = new int[original.Length];

Array.Copy(original, copy, original.Length);

copy[0] = 99;

Console.WriteLine(original[0]); // 1
Console.WriteLine(copy[0]);     // 99
```

You can also copy a range of elements:

C#

```
int[] source = { 10, 20, 30, 40, 50 };
int[] destination = new int[3];

Array.Copy(source, 1, destination, 0, 3);

// destination: [20, 30, 40]
```

The parameters are:

C#

```
Array.Copy(sourceArray, sourceIndex,
           destinationArray, destinationIndex,
           length);
```

This is useful when you need control over which elements are copied and where they go.

##### Does `Array.Copy()` deep-clone objects?

No. `Array.Copy()` performs a shallow copy. It copies the elements, but it does not recursively clone the objects referenced by those elements.

For example:

C#

```
class Person
{
    public string Name { get; set; } = "";
}

Person[] original =
{
    new Person { Name = "Alex" }
};

Person[] copy = new Person[original.Length];

Array.Copy(original, copy, original.Length);

copy[0].Name = "Sam";

Console.WriteLine(original[0].Name); // Sam
```

Both arrays contain references to the same `Person` object.

Conceptually:

```
original[0] ----+
                |
                v
             Person
             Name = "Sam"
                ^
                |
copy[0] --------+
```

Changing the object's property through either array affects the same object.

#### 3.2 `Clone()`

`Clone()` creates a shallow copy of the array.

C#

```
int[] original = { 1, 2, 3 };
int[] copy = (int[])original.Clone();
```

For an array of value types, the values are copied. For an array of reference types, the references are copied, not the referenced objects.

C#

```
class Person
{
    public string Name { get; set; } = "";
}

Person[] original =
{
    new Person { Name = "Alex" }
};

Person[] copy = (Person[])original.Clone();

copy[0].Name = "Sam";

Console.WriteLine(original[0].Name); // Sam
```

The two arrays are separate, but both refer to the same `Person` object.

##### Why cast `(Person[])original.Clone()`?

The declared return type of `Clone()` is `object`.

The compiler therefore sees this:

C#

```
object result = original.Clone();
```

But you want a `Person[]`, so you cast it:

C#

```
Person[] cloned = (Person[])original.Clone();
```

The cast tells the compiler to treat the returned object as a `Person[]`. The runtime checks that the object really is compatible with that type.

The cast doesn't make the copy deeper. It only gives the result the array type you need.

##### Are `Array.Copy()` and `Clone()` the same?

For a basic array copy, both perform shallow copying, but their APIs differ.

C#

```
Array.Copy(original, copy, original.Length);
```

`Array.Copy()` copies elements from a source array into a destination array. It supports copying ranges and can copy into an existing destination array.

C#

```
Person[] cloned = (Person[])original.Clone();
```

`Clone()` creates a new array with the same dimensions and element type, then copies the elements into it. It returns `object`, not a strongly typed array, which is why a cast is needed.

So yes, for a simple full-array copy, they produce arrays with the same shallow-copy behavior. But they aren't identical in how you use them.

#### 3.3 `CopyTo()`

`CopyTo()` copies all elements into an existing destination array, starting at a specified destination index.

C#

```
int[] source = { 1, 2, 3 };
int[] destination = new int[5];

source.CopyTo(destination, 1);

// destination: [0, 1, 2, 3, 0]
```

The destination must have enough space for the copied elements.

#### 3.4 `Array.ConstrainedCopy()`

`Array.ConstrainedCopy()` is a specialized copying API that provides stronger guarantees about the destination if the copy fails. It is less commonly needed in everyday application code.

For typical application code, `Array.Copy()` is usually sufficient.

#### Shallow copy vs. deep copy

A shallow copy duplicates the array structure and its element values or references. It doesn't recursively duplicate objects referenced by the array.

A deep copy creates copies of the referenced objects too. There is no universal built-in `Array.DeepCopy()` method because the correct deep-copy behavior depends on the objects and their relationships.

### 4. Removing an element from the middle

Arrays have a fixed length. They don't have a built-in `Remove()` method.

If you need to remove an element while keeping the same array length, you can shift the remaining elements.

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

int indexToRemove = 2;

for (int i = indexToRemove; i < numbers.Length - 1; i++)
{
    numbers[i] = numbers[i + 1];
}

// Last element is now a duplicate.
numbers[^1] = 0;

// Result: [10, 20, 40, 50, 0]
```

This doesn't actually reduce the array's length. It moves the remaining values and places a default value in the last slot.

If you need a genuinely shorter array, create a new one and copy the elements around the removed position:

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };
int indexToRemove = 2;

int[] result = new int[numbers.Length - 1];

Array.Copy(numbers, 0, result, 0, indexToRemove);

Array.Copy(
    numbers,
    indexToRemove + 1,
    result,
    indexToRemove,
    numbers.Length - indexToRemove - 1);

// result: [10, 20, 40, 50]
```

Removing an element this way takes O(n) time because elements may need to be shifted or copied.

If you repeatedly need to insert or remove elements, an array may not be the most suitable structure. We'll explore resizable collections later.

##### What does `numbers[^1]` do?

The `^` operator is the index-from-end operator. It lets you count backward from the end of an array or another type that supports index-from-end access.

For example:

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

Console.WriteLine(numbers[^1]); // 50
Console.WriteLine(numbers[^2]); // 40
Console.WriteLine(numbers[^3]); // 30
```

The indexes work like this:

| Expression    | Equivalent index | Value |
| ------------- | ---------------- | ----- |
| `numbers[0]`  | 0                | 10    |
| `numbers[^1]` | 4                | 50    |
| `numbers[^2]` | 3                | 40    |
| `numbers[^3]` | 2                | 30    |

`^1` means the first element counting from the end. It does not mean index `-1`.

You can also use it with ranges:

C#

```
int[] lastThree = numbers[^3..];
// { 30, 40, 50 }
```

The range `^3..` means start at the third element from the end and continue to the end.

### 5. Important methods and properties of the `Array` API

The `System.Array` class provides many useful static methods and instance properties.

#### 5.1 Properties

| Property      | Description                                                                        | Example               |
| ------------- | ---------------------------------------------------------------------------------- | --------------------- |
| `Length`      | Total number of elements across all dimensions                                     | `matrix.Length`       |
| `Rank`        | Number of dimensions                                                               | `matrix.Rank`         |
| `IsFixedSize` | Indicates whether the array has a fixed size                                       | `numbers.IsFixedSize` |
| `IsReadOnly`  | Indicates whether the array is read-only through the relevant collection interface | `numbers.IsReadOnly`  |

For a rectangular array:

C#

```
int[,] matrix = new int[2, 3];

Console.WriteLine(matrix.Length); // 6
Console.WriteLine(matrix.Rank);   // 2
```

`Length` gives the total element count, while `GetLength(dimension)` gives the length of an individual dimension.

C#

```
Console.WriteLine(matrix.GetLength(0)); // 2
Console.WriteLine(matrix.GetLength(1)); // 3
```

#### 5.2 `Array.IndexOf()` and `Array.LastIndexOf()`

Find the first or last occurrence of a value.

C#

```
int[] numbers = { 10, 20, 30, 20, 40 };

int first = Array.IndexOf(numbers, 20);     // 1
int last = Array.LastIndexOf(numbers, 20);  // 3
int missing = Array.IndexOf(numbers, 99);   // -1
```

These methods perform linear searches, so their typical time complexity is O(n).

#### 5.3 `Array.Find()` and related methods

These methods search using a condition expressed as a predicate.

C#

```
int[] numbers = { 10, 15, 20, 25, 30 };

int first = Array.Find(numbers, n => n > 20);
// 25
```

Related methods include:

| Method            | Purpose                                           |
| ----------------- | ------------------------------------------------- |
| `Find()`          | Returns the first matching element                |
| `FindLast()`      | Returns the last matching element                 |
| `FindAll()`       | Returns an array containing all matching elements |
| `FindIndex()`     | Returns the index of the first match              |
| `FindLastIndex()` | Returns the index of the last match               |
| `Exists()`        | Returns whether at least one element matches      |
| `TrueForAll()`    | Returns whether all elements match                |

Example:

C#

```
int[] numbers = { 10, 15, 20, 25, 30 };

bool hasLargeNumber = Array.Exists(numbers, n => n > 25);
// true

bool allPositive = Array.TrueForAll(numbers, n => n > 0);
// true

int[] evenNumbers = Array.FindAll(numbers, n => n % 2 == 0);
// [10, 20, 30]
```

#### 5.4 `Array.Clear()`

Sets a range of elements to their default values.

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

Array.Clear(numbers, 1, 3);

// [10, 0, 0, 0, 50]
```

For reference-type arrays, clearing sets the selected elements to `null`.

`Clear()` doesn't remove elements or change the array's length.

#### 5.5 `Array.Fill()`

Sets every element in an array or a selected range to the same value.

C#

```
int[] numbers = new int[5];

Array.Fill(numbers, 10);

// [10, 10, 10, 10, 10]
```

You can also fill a range:

C#

```
int[] numbers = { 1, 2, 3, 4, 5 };

Array.Fill(numbers, 99, 1, 3);

// [1, 99, 99, 99, 5]
```

#### 5.6 `Array.Reverse()`

Reverses the order of elements in place.

C#

```
int[] numbers = { 10, 20, 30, 40 };

Array.Reverse(numbers);

// [40, 30, 20, 10]
```

You can reverse only part of an array:

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

Array.Reverse(numbers, 1, 3);

// [10, 40, 30, 20, 50]
```

Reversing n elements takes O(n) time.

#### 5.7 `Array.Resize()`

`Resize()` changes the length of an array by creating a new array when necessary and copying the existing elements.

C#

```
int[] numbers = { 10, 20, 30 };

Array.Resize(ref numbers, 5);

// [10, 20, 30, 0, 0]
```

Shrinking an array truncates the elements beyond the new length:

C#

```
Array.Resize(ref numbers, 2);

// [10, 20]
```

The `ref` parameter matters because `Resize()` may assign a new array reference to the variable.

Despite its name, `Resize()` does not resize the existing array object in place. It may allocate a new array and copy elements, making it an O(n) operation when a new array is required.

#### 5.8 `Array.BinarySearch()`

Searches a sorted array using binary search.

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

int index = Array.BinarySearch(numbers, 30);

// 2
```

Binary search repeatedly halves the remaining search range, giving O(log⁡n) search time.

Important:

* The array must already be sorted according to the same ordering used for the search.

* If the item isn't found, the method returns a negative number encoding the bitwise complement of the insertion index.

* If duplicates exist, it doesn't guarantee which matching duplicate index will be returned.


##### What does "negative number encoding the bitwise complement of the insertion index" mean?

This refers to the return value of `Array.BinarySearch()` when the searched value isn't found.

First, remember that binary search requires the array to be sorted.

C#

```
int[] numbers = { 10, 20, 30, 40, 50 };

int result = Array.BinarySearch(numbers, 30);
// result is 2
```

When the value exists, the method returns its index.

But what if you search for `35`?

C#

```
int result = Array.BinarySearch(numbers, 35);
```

The value isn't there. The method returns a negative number that encodes where the value would be inserted to keep the array sorted.

For this example, `35` would go at index `3`:

```
10, 20, 30, 35, 40, 50
             ^
         insertion index 3
```

The method encodes that insertion index using the bitwise complement operator `~`.

In C#:

C#

```
~3 // -4
```

So the result of searching for `35` is `-4`.

To recover the insertion index:

C#

```
int result = Array.BinarySearch(numbers, 35);

if (result < 0)
{
    int insertionIndex = ~result;
    Console.WriteLine(insertionIndex); // 3
}
```

Why does `~3` equal `-4`? The bitwise complement flips every bit in the integer's binary representation. For signed integers, this is equivalent to `-x - 1`.

Therefore:

| Insertion index | Encoded result |
| --------------- | -------------- |
| 0               | -1             |
| 1               | -2             |
| 2               | -3             |
| 3               | -4             |
| 4               | -5             |

The important distinction is that the negative result is not itself an insertion index. Apply `~` to decode it.

One more detail: if the searched value exists more than once, `BinarySearch()` doesn't guarantee which matching index it returns.

### 6. Sorting arrays

C# provides several ways to sort arrays. The most common is `Array.Sort()`, but you can also provide custom comparison logic.

#### 6.1 Default sorting with `Array.Sort()`

C#

```
int[] numbers = { 40, 10, 30, 20 };

Array.Sort(numbers);

Console.WriteLine(string.Join(", ", numbers));
// 10, 20, 30, 40
```

`Array.Sort()` modifies the original array in place.

For built-in types such as `int`, `double`, `string`, and types implementing `IComparable<T>`, the default ordering is used.

#### 6.2 Sorting in descending order

One approach is to sort ascending and then reverse:

C#

```
int[] numbers = { 40, 10, 30, 20 };

Array.Sort(numbers);
Array.Reverse(numbers);

// 40, 30, 20, 10
```

Another approach is to use a comparer:

C#

```
int[] numbers = { 40, 10, 30, 20 };

Array.Sort(numbers, Comparer<int>.Create((a, b) => b.CompareTo(a)));
```

This sorts in descending order directly.

#### 6.3 Sorting with a custom comparer

Suppose you have a `Person` class and want to sort people by age.

C#

```
public class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

Person[] people =
{
    new() { Name = "Alex", Age = 35 },
    new() { Name = "Sam", Age = 25 },
    new() { Name = "Jordan", Age = 30 }
};

Array.Sort(people, Comparer<Person>.Create(
    (a, b) => a.Age.CompareTo(b.Age)));
```

The comparer determines the ordering. You can use a named `IComparer<Person>` implementation instead when you want reusable sorting logic.

#### 6.4 Sorting with a comparison delegate

For a one-off sort, `Array.Sort()` has an overload that accepts a `Comparison<T>` delegate.

C#

```
Person[] people =
{
    new() { Name = "Alex", Age = 35 },
    new() { Name = "Sam", Age = 25 },
    new() { Name = "Jordan", Age = 30 }
};

Array.Sort(people, (a, b) => a.Age.CompareTo(b.Age));
```

This is concise and useful when the comparison is specific to that operation.

You can also sort by multiple fields:

C#

```
Array.Sort(people, (a, b) =>
{
    int ageComparison = a.Age.CompareTo(b.Age);

    if (ageComparison != 0)
        return ageComparison;

    return string.Compare(
        a.Name,
        b.Name,
        StringComparison.OrdinalIgnoreCase);
});
```

This sorts by age first and uses name to break ties.

#### 6.5 Sorting a range

You don't always need to sort the entire array.

C#

```
int[] numbers = { 90, 40, 30, 20, 10, 80 };

Array.Sort(numbers, 1, 4);

// [90, 10, 20, 30, 40, 80]
```

The parameters specify the starting index and number of elements to sort.

#### 6.6 Sorting parallel arrays

Sometimes you have an array of keys and a corresponding array of values.

C#

```
int[] scores = { 80, 60, 90 };
string[] names = { "Alex", "Sam", "Jordan" };

Array.Sort(scores, names);
```

After sorting:

```
scores: [60, 80, 90]
names:  [Sam, Alex, Jordan]
```

The `names` array is reordered according to the sort order of `scores`. This is useful when two arrays contain related data at matching indices.

#### 6.7 Sorting algorithm and complexity

`Array.Sort()` uses an introspective sorting algorithm (introsort), combining quicksort, heapsort, and insertion sort in different situations.

Its documented worst-case time complexity is O(nlog⁡n).

A few things to remember:

* `Array.Sort()` sorts in place.

* It is not a stable sort. Equal elements aren't guaranteed to retain their original relative order.

* Custom comparison logic must be consistent. An invalid comparer can cause unexpected results or exceptions.

* Sorting a range is useful when only a portion of the array needs to be reordered.

### Interview questions and scenarios

Q1. Why is `Array.Sort()` generally O(nlog⁡n) rather than O(n<sup>2</sup>)?

Because introsort uses efficient comparison-based sorting strategies and switches to heapsort when quicksort recursion becomes too deep, avoiding quicksort's quadratic worst case.

Q2. What is the difference between `Array.Sort()` and `Array.Reverse()`?

`Sort()` arranges elements according to an ordering rule. `Reverse()` simply reverses the current sequence. Reversing an unsorted array does not sort it.

Q3. You need to sort employees by department, then salary descending. How would you implement it?

Use a custom comparison that compares department first and salary second, reversing the salary comparison for descending order.

Q4. You sort objects by age and notice that people with the same age change their relative order. Why?

`Array.Sort()` is not stable. If preserving the relative order of equal-key elements matters, you need a stable sorting approach or an explicit tie-breaker.

Q5. You have an already sorted array and need to find a value efficiently. What would you use?

`Array.BinarySearch()`, provided the array's sorting order matches the search's comparison rules. This provides O(log⁡n) search time.

Q6. You need to remove many elements from the middle of an array. Is repeatedly shifting elements efficient?

Usually not. Each removal may shift many elements, potentially resulting in O(n2)O(n^2)O(n2) work for repeated removals. If you know all the elements to remove, a single pass into a new array may be more efficient. If frequent insertions and removals are a core requirement, consider a different data structure.
