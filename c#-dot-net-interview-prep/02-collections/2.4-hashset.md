# 2.4: `HashSet<T>`

A `HashSet<T>` is a collection that stores unique elements and uses hashing to provide fast membership checks.

Unlike a `List<T>`, a `HashSet<T>` doesn't allow duplicate elements according to its equality comparer.

For example, if you're tracking which user IDs have logged in, you may only care whether an ID has appeared before, not the order or number of occurrences.

C#

```
HashSet<int> loggedInUsers = new();

loggedInUsers.Add(101);
loggedInUsers.Add(102);
loggedInUsers.Add(101);

Console.WriteLine(loggedInUsers.Count); // 2
```

The second attempt to add `101` doesn't create a duplicate.

## 1. Interfaces implemented

`HashSet<T>` implements:

* `ISet<T>` — provides set-specific operations such as union, intersection, and subset checks.

* `IReadOnlySet<T>` — provides read-only set operations.

* `ICollection<T>` — provides general collection operations such as `Add`, `Remove`, and `Count`.

* `IEnumerable<T>` — supports iteration.

It also implements non-generic `ICollection` and `IEnumerable`.

The most important interface to recognize here is `ISet<T>`, because it exposes mathematical set operations.

## 2. Creating and initializing a hash set

C#

```
HashSet<string> languages = new()
{
    "C#",
    "Java",
    "Python"
};
```

You can also specify an initial capacity:

C#

```
HashSet<int> numbers = new HashSet<int>(100);
```

This reserves internal storage for entries. It doesn't create 100 elements.

You can provide a custom equality comparer as well:

C#

```
HashSet<string> names = new(StringComparer.OrdinalIgnoreCase)
{
    "Alice",
    "Bob"
};

Console.WriteLine(names.Add("ALICE")); // false
```

Here, the set treats strings differing only by case as equal.

## 3. Adding, removing, and checking elements

C#

```
HashSet<int> numbers = new();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);
```

`Add()` returns a Boolean:

C#

```
bool added = numbers.Add(20);

Console.WriteLine(added); // false
```

It returns `false` because `20` is already present.

Check membership with `Contains()`:

C#

```
Console.WriteLine(numbers.Contains(30)); // true
Console.WriteLine(numbers.Contains(50)); // false
```

Remove an element:

C#

```
bool removed = numbers.Remove(20);

Console.WriteLine(removed); // true
```

Unlike `List<T>`, a hash set doesn't support index-based access:

C#

```
// numbers[0]; // Not supported
```

A set represents membership, not a sequence of positions.

## 4. How does a `HashSet<T>` work internally?

Like a dictionary, a hash set uses a hash table.

The main difference is what it stores:

* A dictionary stores key-value entries.

* A hash set stores elements themselves.

Conceptually, adding an element works like this:

```
Element
   |
   v
GetHashCode()
   |
   v
Determine bucket
   |
   v
Check for equal elements
   |
   +-- Equal element exists: don't add
   |
   +-- No equal element: insert
```

The hash code helps locate the relevant bucket. Equality comparison determines whether an equivalent element is already present.

Different elements can have the same hash code, so collisions are possible. A hash set handles collisions by checking candidate entries for equality.

As with dictionary keys, elements should not change in ways that affect their equality or hash code while stored in the set.

## 5. Set operations

This is where `HashSet<T>` becomes particularly useful.

Suppose you have two sets:

C#

```
HashSet<int> first = [1, 2, 3, 4];
HashSet<int> second = [3, 4, 5, 6];
```

### Union

The union contains elements present in either set.

C#

```
first.UnionWith(second);

// first now contains 1, 2, 3, 4, 5, 6
```

### Intersection

The intersection contains elements present in both sets.

C#

```
first = [1, 2, 3, 4];
first.IntersectWith(second);

// first now contains 3, 4
```

### Difference

`ExceptWith()` removes elements that occur in another set.

C#

```
first = [1, 2, 3, 4];
first.ExceptWith(second);

// first now contains 1, 2
```

### Symmetric difference

`SymmetricExceptWith()` keeps elements that appear in one set or the other, but not both.

C#

```
first = [1, 2, 3, 4];
first.SymmetricExceptWith(second);

// first now contains 1, 2, 5, 6
```

These operations modify the receiving set.

There are also methods that check relationships without modifying the set:

C#

```
HashSet<int> a = [1, 2];
HashSet<int> b = [1, 2, 3];

Console.WriteLine(a.IsSubsetOf(b));     // true
Console.WriteLine(b.IsSupersetOf(a));   // true
Console.WriteLine(a.Overlaps(b));       // true
Console.WriteLine(a.SetEquals(b));      // false
```

## 6. Iterating over a hash set

C#

```
HashSet<string> languages = ["C#", "Java", "Python"];

foreach (string language in languages)
{
    Console.WriteLine(language);
}
```

You can iterate over its elements, but don't rely on a particular ordering. A `HashSet<T>` doesn't provide a general ordering guarantee.

If order matters, use an ordered collection or sort the elements when you need to present them.

## 7. Time complexity

| Operation         | Average                | Worst case                               |
| ----------------- | ---------------------- | ---------------------------------------- |
| `Add()`           | O(1)                   | O(n)                                     |
| `Remove()`        | O(1)                   | O(n)                                     |
| `Contains()`      | O(1)                   | O(n)                                     |
| `UnionWith()`     | Depends on input sizes | Depends on collisions and implementation |
| `IntersectWith()` | Depends on input sizes | Depends on collisions and implementation |
| `IsSubsetOf()`    | Depends on input sizes | Depends on collisions and implementation |
| Iteration         | O(n)                   | O(n)                                     |

Average O(1) membership operations rely on effective hashing and a reasonable distribution of hash codes. Poor hashing can cause many collisions and degrade performance.

## 8. `HashSet<T>` vs `List<T>` vs `Dictionary<TKey, TValue>`

| Feature            | `List<T>`        | `HashSet<T>`              | `Dictionary<TKey, TValue>` |
| ------------------ | ---------------- | ------------------------- | -------------------------- |
| Stores             | Elements         | Unique elements           | Key-value pairs            |
| Duplicates         | Allowed          | Not allowed by equality   | Keys must be unique        |
| Indexing           | Yes              | No                        | By key                     |
| Membership lookup  | O(n)             | O(1) average              | O(1) average by key        |
| Ordering guarantee | Sequence order   | No general ordering       | No general ordering        |
| Main use           | Ordered sequence | Uniqueness and membership | Key-based lookup           |

For example:

* Use a list if you need to preserve a sequence of events, including repeated events.

* Use a hash set if you need to track which event IDs have already been processed.

* Use a dictionary if you need to map event IDs to event details.

## 9. Other useful APIs

| Method or property      | Purpose                                                         |
| ----------------------- | --------------------------------------------------------------- |
| `Add()`                 | Adds an element if it isn't already present                     |
| `Remove()`              | Removes an element                                              |
| `Contains()`            | Checks membership                                               |
| `UnionWith()`           | Combines elements from another collection                       |
| `IntersectWith()`       | Keeps only shared elements                                      |
| `ExceptWith()`          | Removes elements found in another collection                    |
| `SymmetricExceptWith()` | Keeps elements exclusive to either set                          |
| `IsSubsetOf()`          | Checks whether all elements exist in another set                |
| `IsSupersetOf()`        | Checks whether another set's elements all exist here            |
| `Overlaps()`            | Checks whether at least one element is shared                   |
| `SetEquals()`           | Checks whether two collections contain the same set of elements |
| `EnsureCapacity()`      | Ensures sufficient internal capacity                            |
| `TrimExcess()`          | Reduces unused capacity                                         |
| `Clear()`               | Removes all elements                                            |

## 10. Interview questions and scenarios

Q1. What's the difference between `HashSet<T>` and `Dictionary<TKey, TValue>`?

A hash set stores unique elements and is useful for membership checks. A dictionary stores unique keys associated with values and is useful for retrieving data by key.

Q2. How does `HashSet<T>` prevent duplicates?

It uses hashing to locate a bucket and equality comparison to check whether an equivalent element already exists before inserting.

Q3. When would you choose a hash set over a list?

When uniqueness or frequent membership checks matter more than positional access and ordering.

Q4. Can a hash set contain two objects with different references but equal values?

Not if its equality comparer considers them equal. For example, two separate record instances with the same property values are considered equal by default.

Q5. What happens if an object's hash code changes while it's in a hash set?

The set may no longer be able to locate that element correctly. This is why stable equality and hash-code behavior is important for elements stored in hash-based collections.

Q6. How would you find common elements between two large collections?

A common approach is to use a hash set and `IntersectWith()`, or create a set from one collection and check membership while iterating over the other. This often avoids repeated O(n) list searches.

## Follow-ups

> `Dictionary.Add()` vs `HashSet.Add()`

Dictionary: duplicate keys cause an exception.

C#

```
Dictionary<int, string> employees = new();

employees.Add(101, "Alice");
employees.Add(101, "Bob"); // Throws ArgumentException
```

A dictionary cannot have two entries with equal keys. `Add()` enforces this by throwing an exception if the key already exists.

HashSet: duplicate elements are ignored.

C#

```
HashSet<int> numbers = new();

numbers.Add(10); // true
numbers.Add(10); // false
```

The second insertion doesn't add another element and doesn't throw an exception.

Notice that the method returns a `bool`:

* `true`: the element was successfully added.

* `false`: an equivalent element was already present.

This behavior is intentional. A hash set is designed to maintain uniqueness, so attempting to add a duplicate is a normal situation, not necessarily an error.

If you want to update an existing dictionary entry rather than throw an exception, you can use its indexer:

C#

```
employees[101] = "Bob";
```

> `IsSubsetOf()` vs `Overlaps()`

Both methods compare a set with another collection, but they answer different questions.

* `IsSubsetOf()` asks: Are all elements of this set present in the other collection?

* `Overlaps()` asks: Does this set share at least one element with the other collection?

Consider:

C#

```
HashSet<int> a = [1, 2];
HashSet<int> b = [1, 2, 3];
HashSet<int> c = [2, 4];
HashSet<int> d = [5, 6];
```

| Expression        | Result  | Explanation                 |
| ----------------- | ------- | --------------------------- |
| `a.IsSubsetOf(b)` | `true`  | Both `1` and `2` are in `b` |
| `b.IsSubsetOf(a)` | `false` | `3` is missing from `a`     |
| `a.Overlaps(b)`   | `true`  | They share `1` and `2`      |
| `a.Overlaps(c)`   | `true`  | They share `2`              |
| `a.Overlaps(d)`   | `false` | They share no elements      |

### Visual example

```
a = {1, 2}
b = {1, 2, 3}

IsSubsetOf:
Every element of a is contained in b.
Result: true

Overlaps:
At least one element is shared.
Result: true
```

The key difference is that `Overlaps()` only needs one shared element, while `IsSubsetOf()` requires every element of the calling set to be present in the other collection.

An empty set is a special case worth remembering:

C#

```
HashSet<int> empty = [];
HashSet<int> numbers = [1, 2, 3];

empty.IsSubsetOf(numbers); // true
empty.Overlaps(numbers);   // false
```

An empty set is a subset of every set because it has no elements that violate the subset condition. But it cannot overlap another set because it has no elements to share.
