# 2.3: `Dictionary<TKey, TValue>`

A `Dictionary<TKey, TValue>` stores data as key-value pairs. Each key must be unique, and you use the key to look up its associated value.

For example, imagine storing employee information using employee IDs:

C#

```
Dictionary<int, string> employees = new()
{
    [101] = "Alice",
    [102] = "Bob",
    [103] = "Charlie"
};

Console.WriteLine(employees[102]); // Bob
```

Unlike a list, where you access elements by their position, a dictionary lets you access values using meaningful keys.

## 1. Interfaces implemented

`Dictionary<TKey, TValue>` implements several interfaces:

* `IDictionary<TKey, TValue>` — provides key-value operations such as adding, removing, and looking up entries.

* `IReadOnlyDictionary<TKey, TValue>` — provides read-only access to keys and values.

* `ICollection<KeyValuePair<TKey, TValue>>` — treats dictionary entries as a collection of key-value pairs.

* `IEnumerable<KeyValuePair<TKey, TValue>>` — supports iteration over entries.

* Non-generic interfaces such as `IDictionary`, `ICollection`, and `IEnumerable`.

The distinction between `IDictionary<TKey, TValue>` and `IReadOnlyDictionary<TKey, TValue>` is useful when designing APIs. If a method only needs to read entries, accepting `IReadOnlyDictionary<TKey, TValue>` communicates that intent.

## 2. Creating and initializing a dictionary

C#

```
Dictionary<string, int> ages = new();

ages.Add("Alice", 30);
ages.Add("Bob", 25);
```

You can also initialize it with entries:

C#

```
Dictionary<string, int> ages = new()
{
    { "Alice", 30 },
    { "Bob", 25 }
};
```

Or use collection initializer indexer syntax:

C#

```
Dictionary<string, int> ages = new()
{
    ["Alice"] = 30,
    ["Bob"] = 25
};
```

You can specify an initial capacity:

C#

```
Dictionary<int, string> employees = new(500);
```

This reserves storage for approximately 500 entries initially. It doesn't create 500 entries.

## 3. Adding, accessing, updating, and removing

### Add an entry

C#

```
Dictionary<int, string> employees = new();

employees.Add(101, "Alice");
employees.Add(102, "Bob");
```

A key must be unique. Adding an existing key with `Add()` throws an `ArgumentException`.

C#

```
employees.Add(101, "Charlie"); // Exception
```

### Access a value

C#

```
string name = employees[101];
```

If the key doesn't exist, the indexer throws a `KeyNotFoundException`.

### Update a value

C#

```
employees[101] = "Charlie";
```

If the key exists, the value is updated. If it doesn't exist, the indexer creates a new entry.

This is different from `Add()`, which throws if the key already exists.

### Remove an entry

C#

```
employees.Remove(102);
```

`Remove()` returns `true` if the key was found and removed, otherwise `false`.

### Check whether a key exists

C#

```
if (employees.ContainsKey(101))
{
    Console.WriteLine(employees[101]);
}
```

However, when you need to retrieve a value only if the key exists, `TryGetValue()` is usually preferable.

C#

```
if (employees.TryGetValue(101, out string? name))
{
    Console.WriteLine(name);
}
else
{
    Console.WriteLine("Employee not found");
}
```

This avoids doing a separate key lookup followed by another lookup through the indexer.

## 4. How does a dictionary work internally?

A dictionary uses a hash table.

When you add an entry, the dictionary uses the key's hash code to determine where the entry should be stored.

Conceptually:

```
Key: "Alice"
     |
     v
GetHashCode()
     |
     v
Hash value
     |
     v
Find bucket
     |
     v
Store key-value entry
```

When you look up a key, the dictionary calculates its hash again to locate the relevant bucket. It then compares keys to identify the matching entry.

This is why dictionary lookup is usually O(1), on average.

However, hash codes are not guaranteed to be unique. Different keys can have the same hash code. These situations are called hash collisions.

A dictionary must handle collisions by checking entries within the relevant bucket and comparing keys for equality.

We'll examine buckets, collisions, and resizing in more detail in the hash-table section of the course.

## 5. Equality and custom keys

A dictionary uses equality and hash-code behavior to identify keys.

For example:

C#

```
Dictionary<string, int> scores = new();

scores["Alice"] = 100;

Console.WriteLine(scores["Alice"]); // 100
```

Strings use value-based equality by default, so another string containing `"Alice"` can find the same entry.

For custom key types, you need correct equality and hash-code behavior.

C#

```
public record EmployeeKey(int DepartmentId, int EmployeeId);

Dictionary<EmployeeKey, string> employees = new();

employees[new EmployeeKey(10, 101)] = "Alice";

Console.WriteLine(
    employees[new EmployeeKey(10, 101)]
); // Alice
```

Because `EmployeeKey` is a record, it has generated value equality and matching hash-code behavior.

A key's equality and hash code should remain stable while it is stored in a dictionary. Mutating fields that affect its hash code can make an entry difficult or impossible to find.

## 6. Iterating over a dictionary

C#

```
Dictionary<int, string> employees = new()
{
    [101] = "Alice",
    [102] = "Bob",
    [103] = "Charlie"
};

foreach (KeyValuePair<int, string> employee in employees)
{
    Console.WriteLine($"{employee.Key}: {employee.Value}");
}
```

You can also iterate over keys or values:

C#

```
foreach (int id in employees.Keys)
{
    Console.WriteLine(id);
}

foreach (string name in employees.Values)
{
    Console.WriteLine(name);
}
```

Don't rely on dictionary iteration order as a general contract. If ordering matters, use a collection designed for that purpose or explicitly sort the entries.

## 7. Time complexity

| Operation            | Average | Worst case |
| -------------------- | ------- | ---------- |
| Add                  | O(1)    | O(n)       |
| Lookup by key        | O(1)    | O(n)       |
| Update by key        | O(1)    | O(n)       |
| Remove by key        | O(1)    | O(n)       |
| `ContainsKey()`      | O(1)    | O(n)       |
| `TryGetValue()`      | O(1)    | O(n)       |
| Iterate over entries | O(n)    | O(n)       |

These are general hash-table complexity expectations. Actual behavior depends on hashing, collisions, and implementation details. Individual insertions can also take O(n) when resizing occurs.

## 8. Dictionary vs List

| Feature          | `List<T>`                | `Dictionary<TKey, TValue>`    |
| ---------------- | ------------------------ | ----------------------------- |
| Data structure   | Dynamic array            | Hash table                    |
| Access           | By integer index         | By key                        |
| Lookup           | O(n) by value            | O(1) average by key           |
| Duplicate values | Allowed                  | Allowed                       |
| Duplicate keys   | Not applicable           | Not allowed                   |
| Ordering         | Maintains sequence order | No general ordering guarantee |
| Best suited for  | Ordered sequences        | Fast key-based lookup         |

For example, if you're storing a sequence of tasks and need to display them in order, a list is natural.

If you're storing user information by user ID and frequently need to retrieve a particular user, a dictionary is often more suitable.

## 9. Other useful dictionary APIs

| Method or property    | Purpose                                             |
| --------------------- | --------------------------------------------------- |
| `TryAdd()`            | Adds an entry only if the key doesn't already exist |
| `TryGetValue()`       | Retrieves a value if the key exists                 |
| `ContainsKey()`       | Checks whether a key exists                         |
| `ContainsValue()`     | Checks whether a value exists                       |
| `GetValueOrDefault()` | Returns a value or a default if the key is missing  |
| `EnsureCapacity()`    | Ensures sufficient internal capacity                |
| `TrimExcess()`        | Reduces unused capacity                             |
| `Clear()`             | Removes all entries                                 |
| `Keys`                | Provides access to the keys                         |
| `Values`              | Provides access to the values                       |

A useful example is `TryAdd()`:

C#

```
Dictionary<int, string> employees = new();

bool added = employees.TryAdd(101, "Alice");

Console.WriteLine(added); // true

added = employees.TryAdd(101, "Bob");

Console.WriteLine(added); // false
```

Unlike `Add()`, `TryAdd()` doesn't throw merely because the key already exists.

## 10. Interview questions and scenarios

Q1. Why is dictionary lookup usually O(1)?

Because a hash code helps locate the bucket containing the key, avoiding a linear search through all entries in typical cases.

Q2. What happens if two keys have the same hash code?

A collision occurs. The dictionary must distinguish the keys using equality comparisons within the relevant bucket.

Q3. What happens when a dictionary grows?

Its internal storage may be expanded and entries redistributed into a larger bucket structure. This involves work proportional to the number of entries and can make an individual insertion expensive.

Q4. Why should dictionary keys be immutable?

If fields affecting equality or hash codes change after insertion, the dictionary may no longer locate the entry using the modified key. Immutable keys help preserve consistent lookup behavior.

Q5. What's the difference between `Add()`, the indexer, and `TryAdd()`?

* `Add()` throws if the key already exists.

* The indexer adds a missing key or updates an existing key.

* `TryAdd()` returns `false` if the key already exists and doesn't overwrite its value.

Q6. When would you use `ConcurrentDictionary<TKey, TValue>`?

When multiple threads need to read and modify a dictionary concurrently. It provides thread-safe operations such as `TryAdd()`, `TryUpdate()`, and `GetOrAdd()`. A normal `Dictionary<TKey, TValue>` doesn't support concurrent writes safely.
