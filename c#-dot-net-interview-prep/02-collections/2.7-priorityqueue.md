# 2.7 PriorityQueue<TElement, TPriority>

## 1. What Is a Priority Queue?

A `PriorityQueue<TElement, TPriority>` is a collection where each element is associated with a **priority**, and elements are removed according to priority rather than insertion order.

```csharp
PriorityQueue<string, int> queue = new();

queue.Enqueue("Low priority task", 10);
queue.Enqueue("High priority task", 1);
queue.Enqueue("Medium priority task", 5);

Console.WriteLine(queue.Dequeue());
```

Output:

```text
High priority task
```

The important idea is:

```text
Element                 Priority

"Low priority task"        10
"High priority task"        1  <-- removed first
"Medium priority task"     5
```

In .NET, `PriorityQueue<TElement, TPriority>` is a **min-priority queue** by default.

That means:

```text
smaller priority value = higher priority
```

So:

```csharp
queue.Enqueue("A", 10);
queue.Enqueue("B", 3);
queue.Enqueue("C", 7);
```

will be dequeued as:

```text
B
C
A
```

### Priority queue vs normal queue

A normal `Queue<T>` follows FIFO:

```text
First in -> First out

A -> B -> C

Dequeue()
  |
  v
  A
```

A priority queue follows priority:

```text
Priority

A = 10
B = 3
C = 7

Dequeue()
  |
  v
  B
```

So:

| Collection | Removal order |
|---|---|
| `Queue<T>` | Insertion order |
| `Stack<T>` | Reverse insertion order |
| `PriorityQueue<TElement, TPriority>` | Priority order |

## 2. Creating a PriorityQueue

The basic declaration is:

```csharp
PriorityQueue<string, int> queue = new();
```

The two generic parameters are:

```text
PriorityQueue<TElement, TPriority>
              |          |
              |          +-- Type of priority
              +------------- Type of element
```

For example:

```csharp
PriorityQueue<string, int>
```

means:

```text
Element  = string
Priority = int
```

Another example:

```csharp
PriorityQueue<Job, int>
```

means:

```text
Element  = Job
Priority = int
```

---

## 3. Initialization Options

### 3.1 Empty constructor

```csharp
var queue = new PriorityQueue<string, int>();
```

Creates an empty priority queue.

---

### 3.2 Specify initial capacity

You can provide an initial capacity:

```csharp
var queue = new PriorityQueue<string, int>(100);
```

This creates a priority queue with room for approximately 100 elements before it needs to grow.

You can inspect it with:

```csharp
Console.WriteLine(queue.Capacity);
```

And increase the capacity when needed:

```csharp
queue.EnsureCapacity(200);
```

This is particularly useful when you already know approximately how many elements you will add.

#### Important distinction

```csharp
queue.Count
```

is the number of elements currently stored.

```csharp
queue.Capacity
```

is the amount of storage currently allocated.

For example:

```text
Count    = 50
Capacity = 100
```

means:

```text
50 elements are currently stored
100 element slots are available
```

---

### 3.3 Initialize from an enumerable collection

`PriorityQueue` also supports construction from a collection of element/priority pairs.

```csharp
var items = new[]
{
    ("Task A", 10),
    ("Task B", 1),
    ("Task C", 5)
};

var queue = new PriorityQueue<string, int>(items);
```

Now:

```text
Task A -> 10
Task B -> 1
Task C -> 5
```

and:

```csharp
queue.Dequeue();
```

returns:

```text
Task B
```

The input must provide the element and its corresponding priority.

## 4. Capacity

Unlike `LinkedList<T>`, `PriorityQueue<TElement, TPriority>` has a capacity because its implementation is array-based.

You can specify it:

```csharp
var queue = new PriorityQueue<string, int>(capacity: 100);
```

Check it:

```csharp
int capacity = queue.Capacity;
```

Increase it:

```csharp
queue.EnsureCapacity(500);
```

So the important properties/method are:

```csharp
queue.Count
queue.Capacity
queue.EnsureCapacity(...)
```

### What happens when capacity is exceeded?

When you do:

```csharp
queue.Enqueue("Task", 1);
```

and there isn't enough capacity, the underlying storage grows.

This is similar to `List<T>` and `Queue<T>`.

You generally don't need to manually manage this, but understanding it matters for performance.

---

## 5. Adding Elements — `Enqueue`

The primary operation is:

```csharp
queue.Enqueue(element, priority);
```

Example:

```csharp
var queue = new PriorityQueue<string, int>();

queue.Enqueue("Send email", 5);
queue.Enqueue("Process payment", 1);
queue.Enqueue("Generate report", 10);
```

Conceptually:

```text
Element             Priority

Send email             5
Process payment        1
Generate report       10
```

The priority queue does **not** mean that the elements are stored in sorted order.

This is an important distinction.

You should not think:

```text
[Process payment, Send email, Generate report]
```

as a normal sorted array.

Internally, it maintains a **heap**, which only guarantees enough ordering to efficiently find the highest-priority element.

We'll get to that shortly.

---

## 6. Removing the Highest-Priority Element

Use:

```csharp
Dequeue()
```

Example:

```csharp
var queue = new PriorityQueue<string, int>();

queue.Enqueue("Task A", 10);
queue.Enqueue("Task B", 1);
queue.Enqueue("Task C", 5);

var task = queue.Dequeue();

Console.WriteLine(task);
```

Output:

```text
Task B
```

because:

```text
1 < 5 < 10
```

After that:

```text
Task C
Task A
```

remain.

---

## 7. `TryDequeue`

`Dequeue()` throws if the queue is empty.

```csharp
var task = queue.Dequeue();
```

If the queue might be empty, you can use:

```csharp
if (queue.TryDequeue(out string? task, out int priority))
{
    Console.WriteLine(task);
    Console.WriteLine(priority);
}
```

This gives you both:

```text
element
priority
```

without throwing an exception when the queue is empty.

Conceptually:

```text
TryDequeue()
      |
      +-- element
      |
      +-- priority
```

This is particularly useful when processing queues in loops.

---

## 8. Looking at the Highest-Priority Element — `Peek`

`Peek()` looks at the next element without removing it.

```csharp
var next = queue.Peek();
```

For example:

```csharp
queue.Enqueue("Task A", 10);
queue.Enqueue("Task B", 1);
queue.Enqueue("Task C", 5);

Console.WriteLine(queue.Peek());
```

Output:

```text
Task B
```

But `Task B` remains in the queue.

---

## 9. `TryPeek`

Like `TryDequeue`, there is also:

```csharp
TryPeek()
```

Example:

```csharp
if (queue.TryPeek(out string? element, out int priority))
{
    Console.WriteLine(element);
    Console.WriteLine(priority);
}
```

This lets you inspect both the element and priority without removing it.

---

## 10. `EnqueueDequeue`

There is an operation specifically designed for:

1. Adding an element
2. Immediately removing the highest-priority element

```csharp
var result = queue.EnqueueDequeue("New task", 3);
```

This can be more efficient than separately doing:

```csharp
queue.Enqueue("New task", 3);
var result = queue.Dequeue();
```

The combined operation can perform the required heap work in one operation.

This is useful in algorithms where you repeatedly replace the current highest-priority item.

---

## 11. `DequeueEnqueue`

The reverse operation is:

```csharp
var result = queue.DequeueEnqueue("New task", 3);
```

Conceptually:

```text
1. Remove highest-priority element
2. Insert new element
3. Return removed element
```

Again, this is useful in algorithms where you continuously replace one item with another.

---

## 12. `Clear`

Remove everything:

```csharp
queue.Clear();
```

After:

```csharp
queue.Clear();
```

you have:

```text
Count = 0
```

The queue's capacity and its count are different concepts, so clearing the queue does not mean that its allocated storage necessarily disappears.

---

## 13. What Happens When Priorities Are Equal?

Consider:

```csharp
queue.Enqueue("A", 1);
queue.Enqueue("B", 1);
queue.Enqueue("C", 1);
```

All three have the same priority.

The important point is:

**A `PriorityQueue` does not guarantee FIFO ordering for elements with equal priority.**

So you should not rely on:

```text
A -> B -> C
```

when all priorities are equal.

If your application requires deterministic FIFO behavior among equal-priority items, you need to explicitly encode that behavior into the priority.

For example, you could use a priority containing both:

```text
priority level
sequence number
```

or another appropriate comparer/order strategy.

---

## 14. Custom Priority Types

The priority doesn't have to be an `int`.

For example:

```csharp
PriorityQueue<string, DateTime> queue = new();
```

Now the earliest `DateTime` has the highest priority.

```csharp
queue.Enqueue("Task A", new DateTime(2026, 10, 10));
queue.Enqueue("Task B", new DateTime(2026, 10, 5));
queue.Enqueue("Task C", new DateTime(2026, 10, 20));
```

The order will be:

```text
Task B
Task A
Task C
```

because:

```text
Oct 5 < Oct 10 < Oct 20
```

You can also use other types that have an appropriate ordering.

---

## 15. How Priority Is Determined

By default, the priority queue uses the default comparer for `TPriority`.

Conceptually:

```csharp
Comparer<TPriority>.Default
```

For example:

```csharp
int
```

has natural numeric ordering:

```text
1 < 5 < 10
```

and therefore:

```text
1 = highest priority
```

You can also provide a custom comparer when you need different ordering behavior.

This is useful when the natural ordering of the priority type doesn't match the ordering your application needs.

## 16. Internal Implementation

This is one of the most important parts for interviews.

`PriorityQueue<TElement, TPriority>` is implemented using a **priority heap**.

More specifically, .NET uses an **array-backed quaternary min-heap**.

That means each node can have up to **four children**, rather than the two children of a binary heap.

Conceptually:

```text
                       Root
          /         /       \       \
        Node      Node     Node     Node
       / | | \    /...
```

The root contains the element with the smallest priority.

For example:

```text
                 1
        /     /     \     \
       3      5     7      9
      /|\    ...
     10 12 15
```

The heap property is:

```text
parent priority <= child priority
```

Therefore the smallest priority is always at the root.

---

## 17. Why a Heap?

Suppose we simply stored the elements in an unsorted array:

```text
[10, 3, 7, 1, 5]
```

Finding the smallest priority would require:

```text
O(n)
```

searching through the array.

A heap gives us:

```text
Peek      O(1)
Dequeue   O(log n)
Enqueue   O(log n)
```

That's the fundamental reason priority queues use heaps.

---

## 18. Enqueue Internally

Suppose we have:

```text
        1
      / | \
     3  5  7
```

and insert:

```text
2
```

The new element is initially placed at the next available position.

Then the heap adjusts itself.

Conceptually:

```text
Before:

        1
      / | \
     3  5  7


Insert 2:

         1
      / / \ \
     3  5  7  2
```

Because:

```text
2 < 1
```

is false, no upward movement is needed in this particular example.

If instead we inserted:

```text
0
```

the heap would move it upward until the heap property was restored.

This operation is generally called:

**sift up** / **bubble up**.

---

## 19. Dequeue Internally

The smallest-priority element is at the root.

So:

```csharp
queue.Dequeue();
```

starts by removing the root.

But now there is a hole.

The heap takes an appropriate element from the bottom and moves it into the root position.

Then it moves that element downward until the heap property is restored.

This is called:

**sift down** / **bubble down**.

Conceptually:

```text
Remove:

        1
      / | \
     3  5  7
```

Then restore the heap:

```text
        3
      / | \
     7  5  ...
```

The exact internal arrangement is not a sorted sequence.

---

## 20. Why Isn't a PriorityQueue Sorted?

This is a common interview question.

A priority queue only guarantees that the **highest-priority element is accessible efficiently**.

It does not maintain every element in sorted order.

For example, internally you might have something conceptually like:

```text
        1
      / | \
     5  3  8
    / \
   10 7
```

This satisfies the heap property because every parent has priority less than or equal to its children.

But the elements are clearly not globally sorted:

```text
1, 5, 3, 8, 10, 7
```

That's fine.

The heap only needs to guarantee:

```text
minimum priority = root
```

## 21. Time Complexity

| Operation | Complexity |
|---|---:|
| `Peek()` | O(1) |
| `TryPeek()` | O(1) |
| `Enqueue()` | O(log n) |
| `Dequeue()` | O(log n) |
| `TryDequeue()` | O(log n) |
| `EnqueueDequeue()` | O(log n) |
| `DequeueEnqueue()` | O(log n) |
| `Clear()` | O(n) |
| `Count` | O(1) |
| `Capacity` | O(1) |

The important interview answer is:

```text
Peek      -> O(1)
Enqueue   -> O(log n)
Dequeue   -> O(log n)
```

---

## 22. Memory Characteristics

The priority queue is array-backed.

It stores the heap in contiguous storage rather than allocating an individual node object for every element.

Conceptually:

```text
[element + priority]
[element + priority]
[element + priority]
[element + priority]
```

This generally has better memory locality than a pointer-heavy tree structure.

When the internal array runs out of capacity, it needs to allocate a larger array and copy/move the existing heap data.

Therefore, providing a reasonable initial capacity can be useful when you know the approximate number of elements.

---

## 23. Interfaces

This is an important difference from collections such as `List<T>`.

`PriorityQueue<TElement, TPriority>` is **not** an `IList<T>`.

It is primarily a specialized data structure rather than a general-purpose collection abstraction.

The important enumerable/collection-related interfaces exposed by the type include:

```text
IEnumerable
IEnumerable<(TElement Element, TPriority Priority)>
```

It does **not** implement:

```text
IList<T>
ICollection<T>
ISet<T>
```

This is intentional: a priority queue doesn't expose normal list/set semantics such as arbitrary indexing, `Add(T)`, or set operations.

## 24. PriorityQueue vs Queue

| | `Queue<T>` | `PriorityQueue<TElement, TPriority>` |
|---|---|---|
| Ordering | FIFO | Priority |
| Main removal | `Dequeue()` | `Dequeue()` |
| Priority | No | Yes |
| Typical implementation | Circular array | Quaternary heap |
| Enqueue | O(1) amortized | O(log n) |
| Dequeue | O(1) | O(log n) |
| Peek | O(1) | O(1) |
| Use case | Processing in arrival order | Processing by importance |

Example:

### Queue

```text
Request 1
Request 2
Request 3

-> 1
-> 2
-> 3
```

### PriorityQueue

```text
Request 1 -> priority 10
Request 2 -> priority 1
Request 3 -> priority 5

-> 2
-> 3
-> 1
```

---

## 25. PriorityQueue vs Sorted Collections

You might ask:

> Why not just use a `SortedSet` or `SortedDictionary`?

Because the requirements are different.

If you primarily need:

```text
"Give me the next highest-priority item"
```

a priority queue is a natural choice.

If you need:

```text
"Maintain a collection of all values in sorted order"
```

a sorted collection may be more appropriate.

A priority queue is optimized around:

```text
insert
+
retrieve minimum priority
```

rather than maintaining a globally sorted collection.

## 26. Practical Use Cases

### Task scheduling

```csharp
var tasks = new PriorityQueue<string, int>();

tasks.Enqueue("Background cleanup", 10);
tasks.Enqueue("Process payment", 1);
tasks.Enqueue("Send notification", 5);

while (tasks.Count > 0)
{
    var task = tasks.Dequeue();
    Console.WriteLine(task);
}
```

Processing order:

```text
Process payment
Send notification
Background cleanup
```

---

### Shortest-path algorithms

Priority queues are fundamental to algorithms such as:

- Dijkstra's algorithm
- Best-first search
- A* search

For example, Dijkstra's algorithm repeatedly needs:

```text
Give me the unprocessed node with the smallest known distance.
```

That's exactly the kind of operation a priority queue is designed for.

---

### Job processing

Imagine:

```text
Job                  Priority

Critical production     1
Customer request        2
Normal background job   5
Cleanup                 10
```

A priority queue allows the most important job to be processed first.

---

## 27. When NOT to Use PriorityQueue

Don't use it simply because you need "some queue."

Use `Queue<T>` if:

```text
First in -> First out
```

is what you need.

Don't use it when you need:

- arbitrary indexing
- globally sorted iteration
- fast lookup by key
- uniqueness
- set operations

For those requirements, other collections are more appropriate.

---

## 28. A Practical Example

Suppose you're building an airport operations system.

You receive events:

```text
Flight A -> normal
Flight B -> emergency
Flight C -> delayed
Flight D -> normal
```

You could assign priorities:

```text
Emergency = 1
Delayed   = 2
Normal    = 3
```

Then:

```csharp
var flights = new PriorityQueue<string, int>();

flights.Enqueue("Flight A", 3);
flights.Enqueue("Flight B", 1);
flights.Enqueue("Flight C", 2);
flights.Enqueue("Flight D", 3);
```

Processing:

```csharp
while (flights.Count > 0)
{
    var flight = flights.Dequeue();

    Console.WriteLine(flight);
}
```

The system processes:

```text
Flight B
Flight C
Flight A / Flight D
```

The important point is that `Flight A` and `Flight D` have equal priority, so you should **not assume their relative order**.

If you're asked about `PriorityQueue<TElement, TPriority>` in an interview, remember:

```text
PriorityQueue
    |
    +-- Min-priority queue by default
    |
    +-- Smaller priority = higher priority
    |
    +-- Heap-based
    |
    +-- .NET uses a quaternary heap
    |
    +-- Array-backed
    |
    +-- Peek      O(1)
    +-- Enqueue   O(log n)
    +-- Dequeue   O(log n)
    |
    +-- Has Count and Capacity
    |
    +-- Equal priorities are NOT guaranteed FIFO
```

The single most important conceptual distinction is:

> A priority queue is **not a sorted collection**. It is a collection optimized for efficiently retrieving the element with the highest priority.

## Follow-ups

> Can `PriorityQueue` contain duplicate elements with different priorities?

**Yes.**

`PriorityQueue<TElement, TPriority>` does not require elements to be unique.

```csharp
var queue = new PriorityQueue<string, int>();

queue.Enqueue("Task A", 10);
queue.Enqueue("Task A", 1);
queue.Enqueue("Task A", 5);
```

You now have three separate entries:

```text
Element    Priority
-------    --------
Task A        10
Task A         1
Task A         5
```

They are distinct queue entries even though the element is the same.

They will be dequeued according to priority:

```text
Task A (1)
Task A (5)
Task A (10)
```

This is an important difference from something like `Dictionary<TKey,TValue>`, where keys must be unique.

---

> What happens when multiple items have the same priority?

Suppose:

```csharp
queue.Enqueue("A", 5);
queue.Enqueue("B", 5);
queue.Enqueue("C", 5);
```

All three have the same priority.

**You should not rely on .NET returning them in FIFO order.**

The priority queue guarantees the priority ordering, but **does not guarantee a particular ordering among elements with equal priorities**.

So this:

```text
A
B
C
```

is possible, but so are other orders depending on the heap's internal arrangement.

This is a consequence of the heap implementation.

A heap only guarantees:

```text
parent priority <= child priority
```

It doesn't guarantee that elements with equal priorities maintain insertion order.

### If you need FIFO among equal priorities

You can make the priority itself contain a tie-breaker.

For example:

```csharp
PriorityQueue<string, (int Priority, long Sequence)> queue = new();
```

Then:

```csharp
queue.Enqueue("A", (5, 0));
queue.Enqueue("B", (5, 1));
queue.Enqueue("C", (5, 2));
```

Now the priority ordering is effectively:

```text
Priority  Sequence

5         0    -> A
5         1    -> B
5         2    -> C
```

So the sequence number provides FIFO behavior for equal priority levels.

This is a general technique:

---

> How does .NET choose which one to dequeue when all items are having the same priority? 
You're right. I should have been more precise.

The correct answer is:

**The .NET API contract does not specify which equal-priority element is dequeued first.**

It doesn't have a special rule for equal priorities.

So when `Dequeue()` is called, .NET can return **any one of them**.

After removing it, the heap rearranges the remaining elements. Again, because their priorities are equal, the heap has no reason to preserve their original insertion order.

### So is it random?

Not exactly.

It's **implementation-dependent**, determined by the current internal heap arrangement and the operations that have been performed.

For a particular sequence of operations and a particular .NET implementation, you may observe a consistent order. But **you must not depend on that order**, because it isn't part of the `PriorityQueue` contract.

> If the default ordering doesn't express your business rule, encode the complete ordering into the priority.

---

> How do I make a max-heap?

You can reverse the priority comparison.

For example:

```csharp
var queue = new PriorityQueue<string, int>(
    Comparer<int>.Create((x, y) => y.CompareTo(x)));
```

Now:

```csharp
queue.Enqueue("A", 10);
queue.Enqueue("B", 1);
queue.Enqueue("C", 5);
```

will dequeue:

```text
A
C
B
```

because the comparer makes:

```text
10 > 5 > 1
```

effectively become the priority ordering.

So:

```text
Default comparer
    smallest priority first
          ↓
       min-heap

Reversed comparer
    largest priority first
          ↓
       max-heap behavior
```

Technically, `PriorityQueue` itself is still the same type; you're changing the ordering semantics through the comparer.

---

> Can I define completely custom priority rules? What about instances where I have to support priority based on more than 1 param. Maybe Age first, then Name to break ties.

Yes.

This is one of the most useful features of the generic `TPriority`.

Suppose you want:

```text
Age first
Name second
```

For example:

```text
Age    Name
---    ----
30     Alice
25     Bob
30     Charlie
25     David
```

You could define:

```csharp
PriorityQueue<Person, (int Age, string Name)> queue = new();
```

Then:

```csharp
queue.Enqueue(alice, (30, "Alice"));
queue.Enqueue(bob, (25, "Bob"));
queue.Enqueue(charlie, (30, "Charlie"));
queue.Enqueue(david, (25, "David"));
```

Tuple comparison gives you lexicographical ordering:

```text
Age first
  |
  +-- if equal
        |
        +-- Name
```

So the ordering becomes:

```text
(25, "Bob")
(25, "David")
(30, "Alice")
(30, "Charlie")
```

Therefore:

```text
Bob
David
Alice
Charlie
```

assuming the default tuple comparer is appropriate for your desired ordering.

---

### More complicated priority rules

You aren't limited to tuples.

You can define a dedicated priority type:

```csharp
public record Priority(int Age, string Name);
```

Then:

```csharp
PriorityQueue<Person, Priority>
```

and provide a comparer:

```csharp
var comparer = Comparer<Priority>.Create((x, y) =>
{
    int result = x.Age.CompareTo(y.Age);

    if (result != 0)
        return result;

    return string.Compare(x.Name, y.Name, StringComparison.Ordinal);
});

var queue = new PriorityQueue<Person, Priority>(comparer);
```

Now your business rule is explicit:

```text
1. Compare Age
2. If Age differs -> Age decides
3. If Age is equal -> compare Name
```

This is much more flexible than trying to force everything into a single integer priority.

---

### You can have many levels of priority

For example:

```text
1. Severity
2. Due date
3. Customer tier
4. Creation sequence
```

You could model that as:

```csharp
PriorityQueue<Job, JobPriority>
```

where `JobPriority` contains all those fields and the comparer defines the ordering.

Conceptually:

```text
Severity
   ↓
DueDate
   ↓
CustomerTier
   ↓
SequenceNumber
```

The first field that differs determines which item comes first.

This is a very common pattern in real systems.

---

> Is sift-up / sift-down the same as heapify?

**Not exactly.**

They're related, but **heapify is a broader term**.

### Sift up

Used when an element is inserted near the bottom of the heap.

```text
Insert
  ↓
Place at end
  ↓
Sift up
  ↓
Compare with parent
  ↓
Swap if necessary
```

Example:

```text
        2
      /   \
     5     7
    /
   10
```

Insert `1`:

```text
        2
      /   \
     5     7
    /
   10
   \
    1
```

`1` violates the heap property with its parent.

So it moves upward:

```text
        1
      /   \
     2     7
    /
   5
```

This is **sift up**.

---

### Sift down

Usually used after removing the root.

Suppose:

```text
        1
      /   \
     3     5
    / \
   7   8
```

Remove `1`.

The last element may be moved to the root:

```text
        8
      /   \
     3     5
    /
   7
```

Now `8` violates the heap property.

So it moves downward:

```text
        3
      /   \
     7     5
    /
   8
```

This is **sift down**.

---

### Then what is heapify?

**Heapify generally means transforming data into a valid heap.**

For example, suppose you start with:

```text
[5, 1, 8, 3, 2]
```

and want to turn it into a valid min-heap.

You can use a **bottom-up heap construction algorithm**.

That process performs sift-down operations on appropriate nodes.

So:

```text
Heapify
   |
   +-- uses operations such as sift down
   |
   +-- goal: establish the heap property
```

Therefore:

> **Sift up and sift down are individual heap-maintenance operations. Heapify is the broader process of establishing the heap property, often by performing sift-down operations across the structure.**

---

### One subtle distinction: "heapify" can mean different things

You'll see the terminology used somewhat loosely.

For example, someone might say:

> "Heapify this node."

They may mean:

> "Sift this node down until the heap property is restored."

Whereas in algorithm discussions:

> "Build a heap from this array using heapify."

usually means the **entire bottom-up heap construction process**.

So don't treat these as strict synonyms.

A useful mental model is:

```text
                    HEAP
                     |
              maintain property
                 /       \
            sift up     sift down
                 \       /
                  heapify
             (broader process)
```

## The interview-level picture

For `PriorityQueue`, I would remember it like this:

```text
PriorityQueue<TElement, TPriority>
                |
                v
          array-backed heap
                |
                v
        smallest priority first
                |
        +-------+-------+
        |               |
     Enqueue          Dequeue
        |               |
     sift up          sift down
        |               |
      O(log n)        O(log n)
```

And if the interviewer asks:

> "What if I need a max-heap?"

Answer:

> "Use a custom `IComparer<TPriority>` that reverses the priority ordering."

If they ask:

> "What if I need Age, then Name?"

Answer:

> "Make the priority a composite value, such as a tuple or dedicated priority type, and define the comparer so Age is compared first and Name breaks ties."

If they ask:

> "Does PriorityQueue preserve insertion order for equal priorities?"

Answer:

> **"No. Equal-priority elements are not guaranteed to be dequeued FIFO. If I need that behavior, I'd add a sequence number as a tie-breaker."**
